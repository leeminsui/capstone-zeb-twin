## 1. 왜 하는가

지금 화면은 포스터 발표장에서 노트북(가능하면 스크린)으로 시연할 물건인데 세 가지가 걸린다.

- 화면마다 그림체가 다르다. 예측·종합은 로우폴리 3D, 제어는 납작한 2D 그림, 결과는 캔버스에
  직접 그린 차트다.
- 위계가 없다. 숫자 여섯 개가 같은 크기로 3D 위에 떠 있고 글씨 대부분이 9~10px이다.
- "AI가 만든 것 같다"는 인상을 준다. 둥근 카드, 그림자, 반투명 패널이 원인이다.

사용자가 원하는 것은 **한전 SCADA 같은 감시제어 화면**이다. 현대적이고, 여러 결과가 한눈에
읽히고, 예측 모델과 EHP 제어 알고리즘이 드러나야 한다.

보는 사람은 노트북 앞 1~2m에 서 있는 심사위원과 지나가는 관람객이다. 발표자가 옆에서 조작하며
설명한다. 중간에 와서 보는 사람이 많다.

## 2. 목표 / 하지 않는 것 / 해서는 안 되는 것

**목표**

1. 네 화면이 하나의 감시제어 시스템으로 보인다. 틀, 색, 글꼴, 용어가 같다.
2. 가장 작은 글씨가 13px 이상이고 1~2m 거리에서 핵심 값이 읽힌다.
3. 발전 예측과 실내 제어 화면의 3D가 시안보다 눈에 띄게 좋아진다.
4. 예측 모델과 EHP 제어의 동작 방식이 구조도 한 장으로 설명된다.
5. 인터넷 없이 돌아간다.
6. 키보드만으로 시연할 수 있고, 자리를 비우면 스스로 순환한다.

**하지 않는 것**

- 실시간 서버 연결. 지금처럼 14일 기록 재생이다.
- 휴대폰 화면 대응. 가로 1280px 이상만 맞춘다. 그보다 좁으면 "화면을 넓혀 주세요"를 띄운다. *(작성자 판단)*
- 밝은 테마. 어두운 테마 하나만 만든다. *(작성자 판단 — 아래 6장 참고)*
- 기준 제어(베이스라인)와의 비교. 기록에 비교 데이터가 없다.
- 강화학습 제어기 자체의 구현. 화면에 자리만 만든다.

**해서는 안 되는 것**

- 데이터에 없는 값을 지어내 그리기. 차단기 상태, 구역별 온도, 실내기별 전력 같은 것.
  값이 추정이거나 환산이면 화면에 그렇게 적는다.
- 둥근 카드, 부드러운 그림자, 그라데이션 장식, 반투명 유리 패널.
- 13px 미만 글씨.

## 3. 검토한 방식

**화면 뼈대**

| 방식 | 내용 | 장단점 |
|---|---|---|
| A. 제품형 대시보드 | 틀을 고정하고 가운데만 바뀐다 | 실제 시스템처럼 보이고 여러 값을 한 화면에 담는다. 정보가 많아 멀리서는 덜 읽힌다 |
| B. 발표 장면형 | 한 장면에 메시지 하나, 방향키로 넘김 | 멀리서 가장 잘 읽힌다. 슬라이드처럼 보이고 비교가 어렵다 |
| C. 색·글꼴만 교체 | 구조는 그대로 | 가장 싸다. 위계 문제와 캔버스 화면 문제가 남는다 |

**A를 골랐다.** 포스터 발표는 가까이서 보므로 B의 장점이 필요 없고, "여러 결과를 한눈에"와
"돌아가는 시스템"이라는 요구에 A가 맞는다.

**스타일**

처음 시안은 밝은 바탕의 제품형 스타일이었다. 사용자가 "AI 같다, 한전 SCADA 느낌으로"라고
요청했고, 어두운 감시제어 스타일 시안 세 장을 보고 확정했다.

**세 번째 화면**

작성자가 단선 결선도를 제안했으나 사용자가 알고리즘 구조도를 택했다.

## 4. 화면 뼈대

기준 해상도 1440×900. 1920×1080에서도 깨지지 않아야 한다.

```
┌──────────────────────────────────────────────────────────────┐
│ 시스템 이름   ● 기상수집 ● 발전예측 ● MPC ● EHP      날짜 시각  재생속도 │ 상단 바 50px
├────────┬─────────────────────────────────┬───────────────────┤
│ 화면   │                                 │ 계측값            │
│ 1 발전 │        가운데: 화면별 내용       │  항목 값 단위 상태 │
│ 2 실내 │                                 ├───────────────────┤
│ 3 알고 │                                 │ 이벤트            │
│ 4 결과 │                                 │  시각 구분 내용    │
│────────│                                 │                   │
│ 15분   │                                 │                   │
│ 제어주기│                                 │                   │
├────────┴─────────────────────────────────┴───────────────────┤
│ ❙❙  타임라인 (14일)                                    기간   │ 하단 46px
└──────────────────────────────────────────────────────────────┘
  168px              나머지                      344px
```

- **상단 바**: 시스템 이름 "P2H-EMS 감시제어", 건물 이름, 상태 램프 네 개, 날짜와 시각(시각은
  25px 이상), 재생 속도.
- **상태 램프**: 기상 수집·발전 예측·MPC는 재생 중 항상 초록이다. EHP 램프는 냉방이면 하늘색
  "EHP 냉방", 난방이면 "EHP 난방", 멈추면 회색 "EHP 정지"다.
- **왼쪽 메뉴**: 화면 네 개. 숫자키가 버튼에 보인다. 선택된 화면은 흰 바탕에 검은 글씨.
- **15분 제어 주기**: 기상 수집 → 발전량 예측 → MPC 최적화 → 첫 입력 적용 → EHP 운전. 한 스텝
  안에서 차례로 켜진다. 실제 풀이 시간과 무관한 도식이므로 패널 제목 옆에 "도식"이라고 적는다.
  *(작성자 판단)*
- **계측값 표**: 화면마다 항목이 다르다(5장). 값이 범위를 벗어나면 상태 칸이 노란 "주의"가 된다.
- **이벤트**: 재생 위치에서 거꾸로 최근 9건. 기록에서 뽑는다.
  - 냉방 기동 / 냉방 정지 (`mode` 변화, 기동이면 kW 포함)
  - 쾌적 상한 초과 / 쾌적 범위 복귀 (`rt`와 `ch` 비교)
  - 6시간 예측 갱신 (매시 15분 스텝)
  - 최적화 완료, 첫 제어입력 적용 (현재 스텝)
- **타임라인**: 14일 전체. 태양광 발전이 면적, 냉방 구간이 아래 띠. 클릭하면 이동한다.
- **실험 결과 화면만** 오른쪽 열(계측값·이벤트)을 없애고 가운데를 넓게 쓴다. *(작성자 판단)*

**화면 요약 한 줄.** 가운데 패널 제목 띠 바로 아래에 그 화면의 결론을 한 문장으로 둔다.
중간에 온 사람이 이 문장만 읽고도 무엇을 보는지 알게 하려는 것이다. 16px, 한 줄.

| 화면 | 문장 (재생 값으로 채움) |
|---|---|
| 발전 예측 | "지금 발전량은 15분 전 예측보다 2.6 W 낮습니다." |
| 실내 제어 | "EHP가 54.9 kW로 냉방 중이고 실내는 24.5°C입니다." |
| 알고리즘 | "15분마다 6시간을 예측하고, 그 예측으로 EHP 운전을 다시 계산합니다." |
| 실험 결과 | "냉방의 94%를 태양광 발전 시간에 돌렸습니다." |

## 5. 화면별 내용

### 5.1 발전 예측

가운데는 위아래 둘로 나눈다. 위는 3D, 아래는 추이 차트(높이 약 214px).

**3D — 옥상 태양광 설비**

- 공학 2호관 외관. ㄷ자 4층, 수평 창 띠, E2 타워, 옥상 태양광, 실외기 네 대.
- 어두운 배경, 바닥 격자, 주변 건물은 윤곽 위주.
- 시각에 따라 해 방향이 바뀌고 그림자가 움직인다. 구름량이 많으면 직달광이 약해지고 그림자가
  흐려진다. 밤에는 창에 불이 들어온다.
- 태양광 패널은 발전량에 비례해 밝아진다. 실외기는 냉방 중이면 하늘색으로 켜진다.
- 설비 위 계측 태그 세 개: 옥상 태양광 kW, EHP 실외기 kW와 운전 상태, 계통 수전 kW.
  태그는 화면 밖으로 잘리지 않아야 한다.
- 마우스로 끌어 돌릴 수 있다. 손을 떼면 3초 뒤 기본 시점으로 천천히 돌아간다. *(작성자 판단)*

**시안에서 고쳐야 할 것** — 목표 3번의 기준이다.

- E2 타워가 갈색 덩어리다. 창과 층 구분을 넣는다.
- 주변 건물이 상자뿐이다. 창 띠 정도는 넣되 주 건물보다 어둡게 둔다.
- 계통 수전 태그가 위에서 잘린다.
- 중정에 조경(나무, 전정수)이 없다. 기존 구현에 있던 것을 어두운 톤으로 옮긴다.
- 태양광에서 건물, 계통에서 건물로 가는 점선이 정지해 있다. 흐르는 방향으로 움직인다.

**추이 차트 — 발전량 추이와 6시간 예측**

- 지난 3시간 실측(흰 실선), 현재 6시간 예측(주황 실선), 1·2시간 전 예측(주황 점선).
- "현재" 세로선, 예측 구간에 옅은 바탕.
- 단위 W. 대전 실증 패널 값임을 제목 띠에 적는다.

**계측값**: 일사량, 구름량, 외기온도, 15분 뒤 예측, 실측, 예측 오차, 건물 환산 발전, 계통 수전.

### 5.2 실내 제어

**3D — 3층 사무실**

- 지붕과 앞·오른쪽 벽을 걷어낸 단면을 위에서 비스듬히 내려다본다. 원근 없는 직교 투영.
  예전의 "방 안에 들어가는" 시점은 좁고 답답해서 쓰지 않는다.
- 뒷벽은 커튼월. 낮에는 밝고 밤에는 어둡다.
- 책상 열 자리 안팎, 의자, 모니터, 사람. 업무시간(08:00~19:30)에만 사람이 앉아 있고 두 명이
  통로를 오간다. 밤에는 비고 조명이 꺼진다. *(기존 2D 화면의 동작을 3D로 옮김)*
- 천장 카세트형 실내기 세 대. 냉방 중이면 켜지고, 아래로 퍼지는 원뿔과 바닥의 원이 보인다.
  공기 입자가 원뿔 안에서 아래로 흐른다. 농도와 속도는 `pc`에 비례. 난방이면 주황.
- 태그: 실내기마다 "EHP-n 냉방 운전/정지", 실내온도(범위를 넘으면 노란 테두리와 "상한 +0.4"),
  창밖 일사.
- 실내기별 전력과 구역별 온도는 **표시하지 않는다.** 데이터에 총합과 실내온도 하나만 있다.

**시안에서 고쳐야 할 것**

- 사람이 상자와 공이다. 앉은 자세(상체, 팔, 다리)와 선 자세를 구분해 다시 만든다.
- 책상 위가 비어 있다. 모니터 외에 키보드, 서류 정도.
- 원뿔이 거의 안 보인다. 입자를 넣고 바닥 원을 또렷하게.
- 기둥, 화분, 끝쪽 회의실 유리벽 등 사무실로 읽히게 하는 요소가 없다.
- 방이 화면 가운데에 작게 떠 있다. 패널을 채우도록 맞춘다.

**추이 차트 — 실내온도와 냉방 전력, 최근 24시간**

- 위: 실내온도 선과 쾌적 범위 띠(초록). 세로축 °C.
- 아래: 냉방 전력 막대. 두 축을 겹치지 않고 위아래 두 칸으로 나눈다.

**계측값**: 실내온도, 쾌적 범위, 외기온도, EHP 운전, EHP 소비전력, 건물 부하, 태양광 발전, 요금 단가.

### 5.3 알고리즘

3D 없이 구조도 한 장. 위는 발전 예측, 아래는 EHP 제어.

```
[발전 예측]
 기상 예보 ──┐
 현장 센서 ──┼─▶ 예측 모델 ─▶ 6시간 예측 24칸 ─▶ ×3600 건물 환산
 발전 실측 ──┘                       │
                                     ▼
[EHP 제어]
 발전 예측 24칸 ─┐
 전기요금 단가 ──┤
 실내 상태 ──────┼─▶ 제어기 [MPC 운영 중 | 강화학습 예정] ─▶ 6시간 운전 계획
 외기온도 예보 ──┘                                             │ 첫 칸만 실행
                                                               ▼
        15분 뒤 다시 측정 ◀── 건물 ◀── EHP
```

- 입력 상자에는 실제 값의 작은 선 그래프나 24칸 색띠가 들어간다.
- 재생하면 15분마다 칸의 밝기와 숫자가 바뀐다. 15분 제어 주기 램프와 맞춰, 지금 단계에
  해당하는 상자의 테두리가 밝아진다.
- 제어기 상자는 탭 두 개다. "MPC 운영 중"이 선택돼 있고 "강화학습 예정"은 꺼져 있다.
  제어기 내용은 설정 객체 하나로 분리해서, 강화학습이 들어오면 그 객체만 바꾸면 되게 한다.

**미확정 — 구조가 추측이다.** 사용자가 "일단 추측으로"라고 했다.

- 예측 모델 내부(인코더, 디코더, 어텐션, 물리 제약 출력, 시드 3개 평균)는 대화와 모델 교체
  문서의 단어로 짠 것이다. 실제 층 구성은 확인하지 못했다.
- MPC의 목표("6시간 전기요금 합계 최소")와 조건 네 줄(쾌적 범위, RC 열 모델, EHP 용량,
  태양광 자가소비)도 추정이다.
- 그래서 **구조도의 상자·문구·화살표를 코드에 박지 않고 설정 데이터로 둔다.** 코드를 확인한 뒤
  그 데이터만 고친다. 확정 전까지 패널 제목 띠에 "구조는 추정"이라고 표시한다.
- "6시간 운전 계획" 칸은 MPC가 세운 계획이 아니라 **그 뒤 6시간 동안 실제 실행된 값**이다.
  계획은 기록에 없다. 상자에 그렇게 적는다.

**계측값**: 15분 뒤 예측, 6시간 예측 합계, 건물 환산 발전, 요금 단가, 실내온도, 쾌적 범위,
EHP 지령, EHP 소비전력.

### 5.4 실험 결과

오른쪽 열 없이 가운데 전체를 쓴다. 구성은 `mock/results-light.png`를 따르고 스타일만
감시제어로 바꾼다. 재생 위치와 무관한 14일 전체 집계다.

- **왼쪽 패널, 태양광 발전량 예측**
  - 큰 숫자 R² 0.854
  - MAE 3.95 W, nMAE 5.8 %
  - 예측 대 실측 산점도. 대각 점선. 현재 재생 위치의 점을 강조.
  - 하늘 상태별 예측 치우침 막대: 맑음 −6.7 W, 구름 −5.3 W, 흐림 −0.2 W
- **오른쪽 패널, EHP 냉방 제어**
  - 큰 숫자 94 % — 냉방 370회 중 346회가 태양광 발전 중
  - 칸 370개(와플). 발전 중 가동은 하늘색, 아니면 회색
  - 건물이 쓴 전기 64,839 kWh의 출처: 태양광 21.6 % / 계통 수전. 긴 막대 하나를 둘로 나눔
  - 14일 전기요금 153만 원, 하루 평균 10.9만 원
- **아래 띠, 하루씩 보면**: 14일 각각의 태양광 발전·계통 수전 막대와 하늘 상태. 현재 재생 중인
  날을 강조.

숫자는 코드에서 `zeb_window.js`로부터 계산한다. 문서의 숫자를 박아 넣지 않는다.

**사용자가 정한 것**: 예측 지표는 **밤을 포함한 전 구간(1,344스텝) 기준**이다. 낮시간만 보면
R² 0.744다. 하늘 상태별 치우침만 낮시간 기준이다. README에 두 값이 다 있다.

**미결 — 사용자 결정 필요**: "업무시간 쾌적 범위 유지 36 %"를 화면에 넣을지. 정직한 숫자지만
포스터 앞에서 질문을 부른다. 결정 전까지는 **넣지 않는 것**으로 구현하고, 한 줄로 켤 수 있게
둔다.

**색** — 뜻이 고정이다. 네 화면 모두 같다.

| 역할 | 색 | 시안 값 |
|---|---|---|
| 바탕 | 검정에 가까운 청흑 | `#06090C` |
| 패널 | | `#0C1116` |
| 패널 제목 띠 | | `#121A21` |
| 테두리 | | `#25313B` |
| 글씨 | | `#E8EFF4` |
| 보조 글씨 | | `#93A4B1` |
| 흐린 글씨 | | `#5E6E7A` |
| 태양광 | 주황 | `#FFB020` |
| 냉방 | 하늘색 | `#3EC5FF` |
| 계통 전기 | 보라 | `#D77BFF` |
| 정상 | 초록 | `#3DDC84` |
| 주의 | 노랑 | `#FFD60A` |
| 경보 | 빨강 | `#FF5247` |

- 태양광·냉방·계통 세 색은 차트 색 검사기(색각 이상 구분, 바탕 대비)를 어두운 바탕 기준으로
  통과해야 한다. 통과하지 못하면 가장 가까운 통과 값으로 옮긴다.
- 상태색(초록·노랑·빨강)은 상태에만 쓴다. 차트 계열 색으로 쓰지 않는다. 쾌적 범위 띠는 "정상
  범위"이므로 초록을 쓴다.
- 차트 안의 글자는 계열 색을 쓰지 않는 것이 원칙이지만, 감시제어 화면의 관례에 따라 **계측값
  숫자와 설비 태그의 값**에는 그 설비의 색을 쓴다. 축 눈금과 설명 글은 글씨 색을 쓴다.
  *(작성자 판단)*

**글꼴**

- Pretendard Variable 하나. 숫자는 고정폭 숫자(`tnum`).
- 크기 단계: 13 / 14 / 16 / 18 / 26 / 큰 숫자 56 이상(결과 화면).
- 한글 줄바꿈은 `word-break: keep-all`.

**형태**

- 모서리 0. 패널은 1px 테두리. 그림자 없음. 반투명 없음(3D 위 태그 배경만 90 % 불투명).
- 패널마다 높이 30px 제목 띠. 왼쪽에 이름, 오른쪽에 보조 정보.
- 램프는 지름 10px 원에 같은 색 번짐.

**밝은 테마를 만들지 않는 이유.** 처음에는 프로젝터용으로 밝은 테마도 만들겠다고 했으나,
감시제어 스타일은 어두운 화면이 정체성이고 발표가 노트북 위주의 포스터 형식으로 정해졌다.
두 테마를 유지하는 비용이 크다. 필요해지면 색 토큰만 갈아 끼우면 되도록 모든 색을 CSS
변수로 둔다.

**움직임**

- 화면 전환은 가운데 내용만 0.2초 페이드. 틀은 움직이지 않는다.
- 값이 "주의"로 바뀌는 순간 상태 칸이 한 번 깜빡인다.
- `prefers-reduced-motion`이면 3D 자동 회전과 입자를 멈춘다.

## 8. 구조와 제약

- **파일을 나눈다.** 지금은 `index.html` 하나에 85 KB가 들어 있다. 다음처럼 쪼갠다.
  *(작성자 판단)*

  ```
  index.html
  css/app.css              토큰, 틀, 패널, 표
  js/data.js               zeb_window.js 읽기, 빈 값 메우기, 보간, 집계, 이벤트 추출
  js/shell.js              상단 바, 메뉴, 계측값 표, 이벤트, 타임라인, 키보드, 자동 순환
  js/chart.js              추이 차트, 산점도 등 2D 그리기 공용
  js/scene-exterior.js     발전 예측 3D
  js/scene-room.js         실내 제어 3D
  js/view-forecast.js      화면 1
  js/view-room.js          화면 2
  js/view-algo.js          화면 3 (+ 구조도 설정 데이터)
  js/view-results.js       화면 4
  vendor/three.min.js      r128
  vendor/PretendardVariable.woff2
  data/zeb_window.js       그대로
  ```

- **빌드 단계 없음. ES 모듈을 쓰지 않는다.** 파일을 더블클릭(`file://`)해도 열려야 하는데
  모듈은 거기서 막힌다. 일반 `<script>` 태그와 전역 이름공간 하나(`ZEB`)를 쓴다.
- **외부 요청 0건.** Three.js와 글꼴을 저장소에 넣는다. 발표장 와이파이를 믿지 않는다.
  Three.js는 지금 쓰는 r128을 유지한다.
- 실험 결과와 알고리즘 화면은 캔버스가 아니라 HTML과 SVG로 만든다. 글자가 선명하고 고치기 쉽다.
  추이 차트는 매 프레임 다시 그리므로 캔버스를 써도 된다.
- 한 번에 3D 장면 하나만 렌더링한다. 화면 1·2가 아니면 렌더링을 멈춘다.
- 기존 2D 사무실 그림(`drawRoom`), 캔버스 결과 화면(`drawResults`), "건물 전체" 3D 전경 화면은
  없앤다.
- 데이터 형식(`data/zeb_window.js`)과 추출 스크립트(`scripts/export_window.py`)는 건드리지 않는다.
- 배포는 지금처럼 GitHub Pages, 같은 주소.

**정직 표시** — 화면에 반드시 들어가야 하는 문구.

- "건물 환산": 대전 실증 패널 예측에 3600을 곱한 값이라는 것. 알고리즘 화면에 "× 3600".
- 추이 차트와 산점도의 단위 W가 실증 패널 한 장의 값이라는 것.
- 알고리즘 화면의 "구조는 추정"(확정 전까지)과 "이후 6시간 실제 운전값".
- 15분 제어 주기의 "도식".

**값의 정의** — 화면마다 같은 뜻으로 쓴다.

| 값 | 정의 |
|---|---|
| 예측 오차 | 실측 − 15분 전 예측 (`meas − fc`). 음수면 예측이 높았다 |
| 실내온도 "주의" | `rt > ch + 0.05` 또는 `rt < cl − 0.05` |
| 발전 중 냉방 | 냉방 스텝(`mode == 1`) 가운데 `pvs > 10 kW`인 것 |
| 하늘 상태 | 구름량 `cc` 기준. 0.35 미만 맑음, 0.7 미만 구름, 그 이상 흐림. 하루 단위는 09~17시 평균 |
| 태양광 자가 사용량 | 건물 부하 − 계통 수전 (14일 합) |
| 낮시간 | 예측 또는 실측이 1 W를 넘는 스텝 |

밤이나 발전이 0일 때의 요약 문장("지금은 발전이 없습니다" 등)은 만드는 사람이 정한다.

## 10. 다 됐는지 확인하는 법

- 네 화면을 1440×900과 1920×1080에서 캡처해 겹침·잘림이 없는지 본다.
- 콘솔 오류 0건.
- 네트워크를 끊고 `file://`로 열어 네 화면이 모두 뜨는지, 외부 요청이 0건인지 본다.
- 화면의 모든 글씨가 13px 이상인지 계산된 스타일로 확인한다.
- 세 계열 색이 색 검사기를 통과하는지 확인한다.
- 14일을 12시간/초로 끝까지 재생해 오류 없이 처음으로 돌아오는지 본다.
- 60초 방치 후 자동 순환이 시작되고 키 입력으로 멈추는지 본다.
- 결과 화면의 숫자가 README의 "실험 결과" 표와 일치하는지 대조한다.
